## 二、根因分析

### 2.1 P0-UI：样式问题

**现象**：
- **首页 (pages/main/index)**: 正常渲染
- **服务页 (pages/services/index)**: 组件渲染但布局崩溃

**根因**：
小程序侧 Tailwind 不完整，`className` 中的样式类无法生效，导致布局丢失。

### 2.2 P0-DATA：React Query 兼容性问题（新发现 2025-12-18）

**现象**：
- 服务页布局正常后，显示"暂无服务"
- 控制台显示 `isLoading: true` → `false`，但 `data: undefined`
- **关键**：`queryFn` 内的日志从未输出，说明函数根本未执行

**调试过程**：
```
// 第一次渲染
[ServicesPage] 服务列表 Query 状态: {
  data: undefined, 
  isLoading: true, 
  isFetching: true,  ← React Query 认为正在请求
  isError: false
}

// 第二次渲染
[ServicesPage] 服务列表 Query 状态: {
  data: undefined,   ← 但数据为空！
  isLoading: false, 
  isFetching: false, ← 请求"完成"了
  isError: false     ← 也没有错误
}

// 但 queryFn 内的日志从未出现！
```

**验证**：直接调用 API（绕过 React Query）成功返回数据：
```
[ServicesPage] ✅ API 直接调用成功: {data: Array(5), total: 17, page: 1, pageSize: 5}
```

**根因**：
React Query 的 `queryFn` 在小程序环境中未被正确执行。可能原因：
1. Taro 的模块打包机制与 React Query 内部的 Promise 调度冲突
2. React Query 依赖的某些浏览器 API（如 `window.addEventListener`）在小程序中不可用
3. QueryClient 实例在 Taro 页面切换时状态异常

**解决方案**：使用 `useState + useEffect` 替代 `useQuery`（见规则 4）

**对照验证**：

| 组件 | 写法 | 结果 |
|------|------|------|
| BrandSection | className + 完整 style | ✅ 正常 |
| CategorySection | className + 完整 style | ✅ 正常 |
| ServicesPage | className + 部分 style | ❌ 布局崩 |

## 三、硬性规则（Code Review 判定标准）

### 规则 1：布局与结构样式必须在 style 中完整表达

**强制项**（小程序不允许只靠 className）：

| 属性类别 | 必须在 style 中定义的属性 |
|----------|--------------------------|
| Flex 布局 | `display`, `flexDirection`, `alignItems`, `justifyContent`, `gap`, `flex`, `flexWrap`, `flexShrink`, `flexGrow` |
| Grid 布局 | `display: 'grid'`, `gridTemplateColumns`, `gridGap` |
| 定位 | `position`, `top`, `right`, `bottom`, `left`, `zIndex` |
| 尺寸 | `width`, `height`, `minWidth`, `minHeight`, `maxWidth`, `maxHeight` |
| 溢出 | `overflow`, `overflowX`, `overflowY` |

**判定标准**：
```tsx
// ❌ 不通过：flex 布局只在 className
<Box className='flex items-center gap-2'>

// ✅ 通过：style 中有完整等效
<Box
  className='flex items-center gap-2'
  style={{
    display: 'flex',
    alignItems: 'center',
    gap: 8,
  }}
>
```

---

### 规则 2：className 只允许承载「Web 优化」，不得成为「唯一来源」

**允许 className 单独存在**（非布局关键）：
- 语义类：`text-sm`, `font-medium`, `font-bold`
- 圆角类：`rounded-lg`, `rounded-full`（建议 style 补等效）
- 过渡类：`transition-all`, `duration-200`（小程序会忽略，无害）

**禁止 className 作为唯一来源**（布局关键）：
- `flex`, `inline-flex`, `grid`, `block`, `hidden`
- `items-*`, `justify-*`, `gap-*`, `space-*`
- `w-*`, `h-*`, `min-h-*`, `max-w-*`
- `p-*`, `m-*`, `px-*`, `py-*`, `pt-*`, `pb-*`, `pl-*`, `pr-*`
- `absolute`, `relative`, `fixed`, `sticky`
- `top-*`, `left-*`, `right-*`, `bottom-*`, `z-*`
- `overflow-*`

**判定标准**：
```tsx
// ❌ 不通过：min-h-full 是布局关键，只有 className
<Box className='min-h-full pb-14' style={{ backgroundColor: bgColor }}>

// ✅ 通过：布局属性在 style 中完整定义
<Box
  className='min-h-full pb-14'
  style={{
    minHeight: '100%',
    paddingBottom: 56,
    backgroundColor: bgColor,
  }}
>
```

---

### 规则 3：wxScale 只作用于「视觉尺寸」，不作用于「逻辑布局」

**定义**：
```tsx
import { isWxEnvironment } from '../../platform/env'
const wxScale = isWxEnvironment() ? 1.15 : 1
```

**必须乘 wxScale**（视觉尺寸）：

| 属性 | 示例 |
|------|------|
| 字号 | `fontSize: 14 * wxScale` |
| 行高 | `lineHeight: 20 * wxScale` |
| 图标尺寸 | `width: 24 * wxScale, height: 24 * wxScale` |
| 间距 | `padding: 12 * wxScale`, `gap: 8 * wxScale`, `margin: 16 * wxScale` |
| 圆角 | `borderRadius: 8 * wxScale` |

**禁止乘 wxScale**（逻辑布局）：

| 属性 | 说明 |
|------|------|
| `flex: 1` | 弹性比例，不是尺寸 |
| `display`, `flexDirection` | 结构属性 |
| `alignItems`, `justifyContent` | 对齐方式 |
| `position` | 定位方式 |
| `zIndex` | 层级顺序 |
| 百分比值 | 如 `width: '100%'` |

**判定标准**：
```tsx
// ❌ 不通过：flex: 1 乘了 wxScale
style={{ flex: 1 * wxScale }}

// ❌ 不通过：fontSize 没乘 wxScale
style={{ fontSize: 14 }}

// ✅ 通过
style={{
  flex: 1,                    // 逻辑布局，不乘
  fontSize: 14 * wxScale,     // 视觉尺寸，乘
  gap: 8 * wxScale,           // 视觉尺寸，乘
}}
```

---

### 规则 4：小程序环境使用 useState + useEffect 替代 useQuery

**背景**：
React Query 的 `useQuery` 在小程序环境中存在兼容性问题，`queryFn` 可能不被执行。

**判定标准**：
```tsx
// ❌ 不通过：在小程序渲染的组件中使用 useQuery
const { data } = useQuery({
  queryKey: ['services'],
  queryFn: () => api.getServices(),
})

// ✅ 通过：使用 useState + useEffect
const [services, setServices] = useState([])
const [loading, setLoading] = useState(true)

useEffect(() => {
  api.getServices()
    .then(result => setServices(result.data))
    .catch(console.error)
    .finally(() => setLoading(false))
}, [])
```

**适用范围**：
- ✅ 在 `TerminalPreview` 内部渲染的页面组件（ServicesPage、ProfilePage 等）
- ✅ 小程序独立页面（pages/services/index.tsx 等）
- ❌ Web 端组件可继续使用 React Query

---

### 规则 5：图标必须通过 size 和 color props 设置尺寸颜色

**背景**：
`lucide-compat` 图标组件底层使用 `Icon` 组件，通过 `style.width/height` 设置尺寸**无效**。

**判定标准**：
```tsx
// ❌ 不通过：通过 style 设置图标尺寸
<Star style={{ width: 12 * wxScale, height: 12 * wxScale, color: '#fbbf24' }} />

// ✅ 通过：通过 props 设置
<Star size={12 * wxScale} color="#fbbf24" />
```

**适用组件**：
所有从 `lucide-compat` 导入的图标组件：`Star`, `Heart`, `Search`, `ChevronDown`, `Clock`, `Share2` 等。

---

### 规则 6：禁止在组件中使用 `<style>` 标签

**背景**：
小程序不支持内联 `<style>` 标签，会导致 `Template 'tmpl_0_style' not found` 错误。

**判定标准**：
```tsx
// ❌ 不通过：直接使用 <style> 标签
<div>
  <style>{`.scrollbar::-webkit-scrollbar { display: none; }`}</style>
</div>

// ✅ 通过：添加浏览器环境判断
<div>
  {isBrowserEnvironment() && (
    <style>{`.scrollbar::-webkit-scrollbar { display: none; }`}</style>
  )}
</div>

// ✅ 推荐：将样式移到 app.scss
```

**全局样式位置**：`miniapp-shell/src/app.scss`

---

### 规则 7：圆形按钮必须固定宽高并使用 Box 替代 Button

**背景**：
小程序中 `Button` 组件有默认样式，可能导致圆形按钮变成椭圆。

**判定标准**：
```tsx
// ❌ 不通过：Button + padding 实现圆形
<Button
  style={{
    padding: 4 * wxScale,
    borderRadius: 9999,
  }}
>
  <Heart size={12} />
</Button>

// ✅ 通过：Box + 固定宽高
<Box
  onClick={handleClick}
  style={{
    width: 26 * wxScale,
    height: 26 * wxScale,
    minWidth: 26 * wxScale,
    minHeight: 26 * wxScale,
    borderRadius: '50%',
    display: 'flex',
    alignItems: 'center',
    justifyContent: 'center',
  }}
>
  <Heart size={12} color="#fff" />
</Box>
```

const [data, setData] = useState<DataType[]>([])
const [loading, setLoading] = useState(true)
const [error, setError] = useState<string | null>(null)

### 2.3 P0-ICON：图标尺寸与颜色问题（新发现 2025-12-18）

**现象**：
- 排序菜单图标过大、颜色过深
- 评分/收藏等图标尺寸不受控制
- 心形图标在小程序中显示为空心，Web 端为实心

**根因**：
1. `lucide-compat` 组件使用 `size` 和 `color` props 传递给底层 `Icon` 组件
2. 通过 `style={{ width, height }}` 设置尺寸**无效**，必须用 `size` prop
3. 小程序使用 iconfont 字体渲染图标，部分图标 Unicode 映射为空心版本

**解决方案**：

```tsx
// ❌ 错误：通过 style 设置图标尺寸
<Star style={{ width: 12 * wxScale, height: 12 * wxScale, color: '#fbbf24' }} />

// ✅ 正确：通过 size 和 color props 设置
<Star size={12 * wxScale} color="#fbbf24" />
```

**心形图标修复**：
```tsx
// miniapp.tsx 中修改 iconfont 映射
'heart': '♥',  // 使用标准 Unicode 实心心形，替换空心 iconfont
```

### 2.4 P0-RUNTIME：`<style>` 标签兼容性问题（新发现 2025-12-18）

**现象**：
- 控制台报错：`Template 'tmpl_0_style' not found`
- 页面渲染异常

**根因**：
小程序不支持内联 `<style>` 标签，Taro 无法将其转换为 WXSS。

**影响文件**：
- `ServicesPage.tsx`（隐藏滚动条样式）
- `ServiceDetailPage.tsx`（富文本样式）
- `CasesPage.tsx`（Tab 滚动条样式）
- `index.tsx`、`CategorySection.tsx`（已有条件判断）

**解决方案**：

```tsx
// ❌ 错误：直接使用 <style> 标签
<style>{`.my-class { display: none; }`}</style>

// ✅ 正确：添加浏览器环境判断
{isBrowserEnvironment() && (
  <style>{`.my-class { display: none; }`}</style>
)}

// ✅ 或者：将样式移到 app.scss（推荐用于全局样式）
// miniapp-shell/src/app.scss
.services-category-scroll::-webkit-scrollbar {
  display: none;
}
```

## 四、项目战略选择

### 确定采用方案

**默认采用「双重样式」模式（className + 完整 style）**

| 方案 | 采用度 | 说明 |
|------|--------|------|
| 双重样式 | **主力** | 所有新代码、改造代码必须遵守 |
| app.scss 补丁 | 兜底 | 只做紧急兜底，不作为依赖 |
| 自动转换工具 | 不采用 | 当前阶段不引入额外复杂度 |

### 理由

1. **app.scss 会失控膨胀**：走"类库维护路线"，每新增一个 Tailwind 类都要手动补
2. **双重样式可控**：代码冗余但行为确定，迁移阶段稳定优先
3. **便于 Code Review**：有明确判定标准，不依赖对 app.scss 的记忆

## 五、代码模板

### 5.1 标准组件结构

```tsx
import { Box, Text, Image, Button } from '../../ui/primitives'
import { isWxEnvironment } from '../../platform/env'

// 1. 定义缩放比例
const wxScale = isWxEnvironment() ? 1.15 : 1

export function MyComponent({ isDarkMode }: { isDarkMode?: boolean }) {
  // 2. 定义颜色变量
  const bgColor = isDarkMode ? '#1a1a1a' : '#ffffff'
  const textColor = isDarkMode ? '#e5e7eb' : '#1f2937'

  return (
    // 3. 容器：布局属性必须在 style
    <Box
      className='flex flex-col min-h-full'
      style={{
        display: 'flex',
        flexDirection: 'column',
        minHeight: '100%',
        backgroundColor: bgColor,
      }}
    >
      {/* 4. 内容行：flex + gap 必须在 style */}
      <Box
        className='flex items-center gap-3 px-4 py-3'
        style={{
          display: 'flex',
          alignItems: 'center',
          gap: 12 * wxScale,
          paddingLeft: 16 * wxScale,
          paddingRight: 16 * wxScale,
          paddingTop: 12 * wxScale,
          paddingBottom: 12 * wxScale,
        }}
      >
        {/* 5. 文本：fontSize 必须乘 wxScale */}
        <Text
          style={{
            fontSize: 16 * wxScale,
            fontWeight: 600,
            color: textColor,
          }}
        >
          标题文本
        </Text>
      </Box>
    </Box>
  )
}
```

## 附录 B：React Query 兼容性问题调试记录

### 问题复现步骤

1. 在 `TerminalPreview` 内部通过 Tab 切换到服务页
2. `ServicesPage` 组件使用 `useQuery` 获取服务列表
3. 控制台观察到 `isFetching: true` → `false`，但 `queryFn` 未执行

### 环境信息

- Taro: 4.1.9
- React Query: @tanstack/react-query 5.x
- 微信基础库: 3.12.0
- 小程序 TARO_ENV: weapp

### 可能的根因假设

1. **Promise 调度问题**：React Query 内部使用的 Promise 调度机制与 Taro 的事件循环冲突
2. **Context 隔离**：Taro 页面切换时 React Context 可能被重新创建
3. **模块实例问题**：webpack alias 导致多个 React Query 实例

### 临时解决方案

使用 `useState + useEffect` 替代 `useQuery`，直接调用 API。
