**代码分析:**

```typescript
// 第 72-84 行
const handleDelete = async (id: string) => {
  if (!confirm('确定要删除这个地址吗？')) return  // ❌ 问题所在

**根因分析:**

  })
  if (!confirm) return
  // ... rest of the code
}
```

#### 问题 #7: 就诊人管理保存功能失效 ✅ 已修复

| 属性 | 详情 |
|-----|------|
| **模块** | 用户端 - 就诊人管理 |
| **位置** | `src/components/terminal-preview/components/pages/patient-edit/PatientEditPage.tsx` |
| **现象** | 添加就诊人后点击保存按钮无效 |
| **预期** | 应可以正常保存就诊人信息 |
| **提报人** | 陈志光 |
| **修复日期** | 2026-02-04 |
| **修复内容** | 将 `onClick` 从条件绑定改为始终绑定 `handleSubmit` |

**代码分析:**

```typescript
// 第 455-471 行
<Box
  onClick={!validateForm() || isSubmitting ? undefined : handleSubmit}
  // ...
>
```

**根因分析:**
1. `validateForm()` 在每次渲染时都会被调用，可能导致性能问题
2. 按钮使用 `Box` + `onClick` 而非原生 `Button`，在小程序中可能存在点击事件问题
3. `onClick` 条件判断可能因 `undefined` 而导致点击事件未绑定

**建议修复:**
1. 使用 `disabled` 状态配合原生 Button 组件
2. 将 `validateForm()` 结果缓存到 state 中
3. 添加点击反馈（loading 状态）

## 五、技术债务 & 改进建议

### 5.1 跨平台兼容性问题

多处使用浏览器原生 API，需替换为 Taro 跨平台 API：

| 原生 API | 替换方案 |
|---------|---------|
| `confirm()` | `Taro.showModal()` |
| `alert()` | `Taro.showToast()` |
| `localStorage` | `Taro.setStorageSync()` |

### 5.2 错误处理

- API 调用缺少用户友好的错误提示
- 建议统一封装错误处理函数

### 5.3 状态管理

- 部分页面的状态更新和缓存策略需优化
- 建议使用 React Query 的 `invalidateQueries` 确保数据同步

### 5.4 代码复用

- 相似功能（如删除确认）可抽取为通用组件
- 建议创建 `useConfirmDialog` Hook
