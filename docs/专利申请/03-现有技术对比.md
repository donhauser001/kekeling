## 一、现有技术检索

### 1.1 技术领域

本发明涉及的技术领域包括：
- 管理后台系统（Admin Dashboard）
- 移动应用预览技术（Mobile App Preview）
- 所见即所得编辑器（WYSIWYG Editor）
- 多角色权限系统（Role-Based Access Control）

### 1.2 现有技术方案

#### 方案一：传统的真机调试模式

**技术描述**：
开发者在管理后台配置内容后，通过真机或模拟器查看实际效果。

**代表产品**：
- 微信开发者工具
- 各种小程序 IDE
- React Native / Flutter 热重载

**局限性**：
| 问题 | 描述 |
|------|------|
| 环境切换成本高 | 需要在电脑和手机之间反复切换 |
| 无法即时预览 | 需要保存、编译、刷新等步骤 |
| 单一视角 | 只能以当前登录用户身份查看 |
| 数据隔离差 | 预览使用真实数据，可能影响生产环境 |

---

#### 方案二：静态设计稿预览

**技术描述**：
提供静态截图或设计稿作为配置参考。

**代表产品**：
- Figma / Sketch 设计稿嵌入
- 静态图片参考

**局限性**：
| 问题 | 描述 |
|------|------|
| 无动态效果 | 无法预览交互动画和数据变化 |
| 数据不同步 | 截图无法反映实际配置效果 |
| 维护成本高 | 每次改动都需要更新截图 |

---

#### 方案三：简易内嵌预览窗口

**技术描述**：
在管理后台内嵌一个简化的预览窗口，通常使用 iframe 或简化组件。

**代表产品**：
- Shopify 主题预览
- WordPress 可视化编辑器
- 部分 CMS 系统

**局限性**：
| 问题 | 描述 |
|------|------|
| 功能简化 | 通常只预览部分页面，非完整应用 |
| 角色单一 | 不支持多用户角色切换 |
| 会话模拟缺失 | 无法模拟登录状态差异 |
| 数据覆盖不完整 | 配置与预览不完全同步 |

---

#### 方案四：微信小程序「体验版」扫码

**技术描述**：
通过扫码打开体验版小程序查看效果。

**局限性**：
| 问题 | 描述 |
|------|------|
| 非即时 | 需要发布体验版后才能查看 |
| 设备依赖 | 需要手机扫码 |
| 数据真实 | 使用真实后端数据 |

---

#### 方案五：Storybook / 组件库预览

**技术描述**：
通过 Storybook 等工具预览独立组件。

**局限性**：
| 问题 | 描述 |
|------|------|
| 组件级别 | 只能预览单个组件，非完整页面流程 |
| 无业务上下文 | 缺少真实的业务数据和流程 |
| 开发者导向 | 非面向运营/管理人员设计 |

### 2.2 核心创新点对比

#### 创新点一：多角色视角切换机制

| 对比维度 | 现有技术 | 本发明 |
|---------|---------|--------|
| **角色支持** | 单一角色（通常为普通用户） | 多角色（用户 / 服务提供者） |
| **切换方式** | 需重新登录不同账号 | 一键切换，无需重新登录 |
| **视角推导** | 手动指定或无推导 | 基于 Token 自动推导 |
| **安全边界** | 无明确边界 | 预览器与真实终端严格分离 |

**创新性说明**：
本发明首创了「视角角色自动推导机制」，根据会话 Token 的存在性和有效性自动推导当前视角，同时支持通过 Props 强制覆盖用于预览调试，且明确划分了预览器与真实终端的安全边界。

---

#### 创新点二：双通道会话模拟架构

| 对比维度 | 现有技术 | 本发明 |
|---------|---------|--------|
| **会话模型** | 单会话（一个 Token） | 双会话（userToken + escortToken） |
| **请求通道** | 统一通道 | 双通道（userRequest / escortRequest） |
| **通道选择** | 无自动选择 | 根据视角自动选择 |
| **Mock 检测** | 无或简单 | 内置 Mock Token 检测器 |

**创新性说明**：
本发明创新性地提出「双通道会话架构」，支持两种角色的 Token 并存，并根据当前视角自动选择对应的请求通道。同时，内置 Mock Token 检测机制，当检测到模拟 Token 时自动切换到 Mock 数据通道，防止模拟操作影响真实后端。

---

#### 创新点三：分层数据覆盖系统

| 对比维度 | 现有技术 | 本发明 |
|---------|---------|--------|
| **数据来源** | 单一来源（API 或配置） | 三层来源（默认值 / API / Props） |
| **合并策略** | 简单覆盖或无覆盖 | 优先级合并（Props > API > 默认） |
| **局部覆盖** | 不支持 | 支持 Partial 类型局部覆盖 |
| **实时同步** | 需保存后刷新 | 配置即时同步到预览 |

**创新性说明**：
本发明提出「三层数据覆盖机制」，通过明确的优先级规则（Props 覆盖 > API 数据 > 默认值）实现灵活的数据合并。管理员在编辑配置时，修改的数据通过 Props 实时传递给预览器，无需保存即可看到效果，大幅提升配置效率。

---

#### 创新点四：页面路由注册表（单一真源）

| 对比维度 | 现有技术 | 本发明 |
|---------|---------|--------|
| **路由管理** | 终端和预览器各自维护 | 统一注册表（单一真源） |
| **入口控制** | 无限制 | 明确定义可入口页面 |
| **参数校验** | 无或松散 | 开发环境严格校验 |
| **通道标注** | 无 | 每个页面标注所需通道 |

**创新性说明**：
本发明引入「页面路由注册表」作为终端路由与预览器路由的单一真源，统一管理 30+ 页面的路由配置。每个页面明确标注是否可作为入口、必填参数、所需请求通道等元数据，在开发环境提供严格的参数校验。

---

#### 创新点五：内置开发调试面板

| 对比维度 | 现有技术 | 本发明 |
|---------|---------|--------|
| **调试工具** | 依赖外部工具（浏览器 DevTools） | 内置调试面板 |
| **信息展示** | 需手动查找 | 实时显示关键状态 |
| **操作能力** | 无 | 支持 Token 注入/清除 |
| **可视化** | 无 | 视角/通道状态可视化 |

**创新性说明**：
本发明内置 DebugPanel 调试面板，实时显示当前视角角色、双 Token 状态、请求通道等关键信息。支持一键注入/清除模拟 Token，方便开发调试。该设计将调试能力集成到预览器内部，无需依赖外部工具。

## 四、新颖性论证

### 4.1 技术新颖性

本发明的技术方案具有以下新颖性：

1. **首次提出「多角色视角切换」在管理后台预览器中的应用**
   - 现有技术通常只支持单一用户角色预览
   - 本发明支持用户和服务提供者两种角色的无缝切换

2. **首次提出「双通道会话模拟架构」**
   - 现有技术使用单一会话模型
   - 本发明创新性地支持双 Token 并存和通道自动选择

3. **首次提出「三层数据覆盖机制」用于实时预览**
   - 现有技术通常采用简单的数据替换
   - 本发明提出明确的优先级合并策略

4. **首次将「页面路由注册表」作为终端与预览器的单一真源**
   - 现有技术终端路由和预览路由各自维护
   - 本发明统一管理，确保一致性

### 4.2 创造性论证

本发明解决了现有技术无法解决的技术问题：

| 技术问题 | 现有技术困境 | 本发明解决方案 |
|---------|------------|--------------|
| 多角色预览 | 需切换账号，效率低 | 视角切换机制 + 双通道架构 |
| 实时同步 | 需保存刷新，体验差 | Props 数据覆盖 + 三层合并 |
| 数据安全 | Mock 调真实接口有风险 | Mock Token 检测 + 通道隔离 |
| 调试困难 | 依赖外部工具 | 内置 DebugPanel |
