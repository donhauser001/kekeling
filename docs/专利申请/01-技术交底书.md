## 三、背景技术

### 3.1 现有技术描述

在当前的软件开发实践中，管理后台与终端应用（如小程序、App、H5）通常是分离开发和部署的。管理员在后台配置内容（如首页布局、营销活动、服务信息等）后，需要通过以下方式验证终端效果：

1. **传统方式一：真机预览**
   - 保存配置后，切换到真实的小程序/App 查看效果
   - 需要反复切换设备，效率低下
   - 无法在配置过程中实时预览

2. **传统方式二：静态截图/设计稿**
   - 提供静态的界面截图作为参考
   - 无法反映真实数据和动态效果
   - 配置变更后截图不同步

3. **传统方式三：简易预览窗口**
   - 部分系统提供简化的预览窗口
   - 通常只支持单一视角（如仅用户视角）
   - 不支持复杂的多角色场景预览

### 3.2 现有技术的不足

| 问题 | 描述 |
|------|------|
| **实时性差** | 配置修改后无法即时看到终端效果 |
| **角色单一** | 无法预览不同用户角色（如普通用户、服务提供者）的界面差异 |
| **会话模拟缺失** | 无法模拟登录状态、权限差异等复杂场景 |
| **数据隔离性差** | 预览数据与真实数据混用，可能产生脏数据 |
| **开发调试困难** | 缺乏调试工具，难以排查界面异常 |

### 3.3 本发明要解决的技术问题

1. 如何在管理后台实现终端界面的实时预览？
2. 如何支持多角色（用户/服务提供者）视角的无缝切换？
3. 如何安全地模拟不同的登录会话状态？
4. 如何实现配置数据与预览界面的实时同步？
5. 如何在预览模式下隔离真实数据，防止副作用？

## 四、发明内容

### 4.1 技术方案概述

本发明提供一种基于管理后台的多角色视角终端实时预览系统，包括：

1. **终端预览器组件**：在管理后台中嵌入的可交互预览窗口，完整还原终端界面
2. **多角色视角切换机制**：支持在用户视角和服务提供者视角之间无缝切换
3. **双通道会话模拟架构**：通过独立的请求通道模拟不同角色的 API 调用
4. **分层数据覆盖系统**：实现配置数据与预览界面的实时同步
5. **开发调试面板**：提供 Token 状态、请求通道、视角角色的实时监控

### 4.3 核心技术特征

#### 特征一：多角色视角切换机制

```typescript
// 视角角色类型定义
type PreviewViewerRole = 'user' | 'escort'

// 视角推导规则
interface ViewerRoleDerivation {
  // 规则 1: 预览器模式 + 显式 Props → 使用 Props 值（强制模拟）
  // 规则 2: 预览器模式 + escortToken 存在 → 'escort'
  // 规则 3: 其他情况 → 'user'
}
```

**技术要点**：
- 视角由 Token 验证结果自动推导，非手动设置
- 预览器模式允许通过 Props 强制模拟视角
- 真实终端禁止手动写入视角，防止越权风险

#### 特征二：双通道会话模拟架构

```typescript
// 双会话模型
interface UserSession {
  token: string      // 用户 Token
  userId: string     // 用户 ID
}

interface EscortSession {
  token: string      // 服务者 Token
  escortId: string   // 服务者 ID
}

// 请求通道选择逻辑
function selectRequestChannel(viewerRole: PreviewViewerRole) {
  return viewerRole === 'escort' ? escortRequest : userRequest
}
```

**技术要点**：
- 双 Token 并存，互不干扰
- 根据视角自动选择请求通道
- Mock Token 检测机制，防止调用真实后端

#### 特征三：分层数据覆盖系统

```typescript
// 数据合并优先级：Props 覆盖 > API 数据 > 默认值
const themeSettings = {
  ...defaultThemeSettings,      // 第三优先级：默认值
  ...fetchedThemeSettings,      // 第二优先级：API 数据
  ...themeSettingsOverride,     // 第一优先级：Props 覆盖
}
```

**技术要点**：
- 三层数据合并机制
- Props 覆盖实现实时预览
- 支持局部覆盖（Partial 类型）

#### 特征四：页面路由注册表（单一真源）

```typescript
// 路由注册表
const ROUTE_REGISTRY = {
  home: { path: '/pages/index', component: 'HomePage', channel: 'user' },
  workbench: { path: '/pages/workbench', component: 'WorkbenchPage', channel: 'escort' },
  // ... 30+ 页面

// 页面元数据
interface PageMetadata {
  entryAllowed: boolean       // 是否允许作为入口
  requiredParams?: string[]   // 必填参数
}
```

**技术要点**：
- 终端路由与预览器路由统一管理
- 页面入口权限控制
- 参数校验机制

#### 特征五：开发调试面板

```typescript
// 调试面板显示信息
interface DebugPanelInfo {
  effectiveViewerRole: 'user' | 'escort'  // 当前视角
```

**技术要点**：
- 实时显示双 Token 状态

## 六、具体实施方式

### 6.1 实施例一：首页配置实时预览

**场景**：管理员在后台配置首页轮播图，需要实时预览终端效果。

**实现步骤**：

1. 管理员进入"首页管理"页面
2. 页面右侧显示终端预览器组件
3. 管理员修改轮播图配置（如上传新图片、调整顺序）
4. 系统通过 Props 将配置数据实时传递给预览器
5. 预览器立即更新显示，无需保存或刷新

```typescript
// 首页管理页面代码示例
function HomepageManagement() {
  const [bannerData, setBannerData] = useState(initialBannerData)
  
  return (
    <div className="flex">
      {/* 左侧：配置编辑区 */}
      <div className="w-1/2">
        <BannerEditor 
          data={bannerData} 
          onChange={setBannerData}  // 修改立即触发
        />
      </div>
      
      {/* 右侧：终端预览器 */}
      <div className="w-1/2">
        <TerminalPreview
          page="home"
          bannerData={bannerData}  // Props 覆盖，实时同步
        />
      </div>
    </div>
  )
}
```

### 6.2 实施例二：陪诊员工作台预览

**场景**：管理员需要预览陪诊员视角的工作台界面。

**实现步骤**：

1. 管理员进入"陪诊员管理"页面
2. 点击预览器的调试面板，切换到"陪诊员视角"
3. 系统自动注入模拟的 escortToken
4. 预览器切换到工作台界面，显示陪诊员专属功能
5. 所有 API 请求通过 escortRequest 通道发送


### 6.3 实施例三：营销活动配置预览

**场景**：运营人员配置优惠券活动，需要同时预览用户领券界面和已领优惠券列表。

**实现步骤**：

1. 运营人员进入"优惠券管理"页面
2. 配置优惠券信息（面额、门槛、有效期等）
3. 预览器显示两种视图：
   - "可领优惠券"页面：用户未领取时的展示
   - "我的优惠券"页面：用户领取后的展示
4. 通过 marketingData 覆盖实时同步配置

```typescript
// 优惠券管理页面代码示例
function CouponManagement() {
  const [couponConfig, setCouponConfig] = useState(initialConfig)
  const [previewPage, setPreviewPage] = useState<'coupons' | 'coupons-available'>('coupons-available')
  
  return (
    <div className="flex">
      <div className="w-1/2">
        <CouponEditor data={couponConfig} onChange={setCouponConfig} />
        
        {/* 预览页面切换 */}
        <div className="flex gap-2 mt-4">
          <button onClick={() => setPreviewPage('coupons-available')}>
            预览领券页
          </button>
          <button onClick={() => setPreviewPage('coupons')}>
            预览我的优惠券
          </button>
        </div>
      </div>
      
      <div className="w-1/2">
        <TerminalPreview
          page={previewPage}
          marketingData={{
            availableCoupons: [couponConfig],  // 可领列表
            coupons: {
              items: [{ ...couponConfig, status: 'available' }],  // 已领列表
            },
          }}
        />
      </div>
    </div>
  )
}
```

## 九、摘要

本发明公开了一种基于管理后台的多角色视角终端实时预览系统及方法。该系统包括：终端预览器组件、视角切换模块、双通道会话模块和数据覆盖模块。通过在管理后台嵌入可交互的终端预览器，实现配置数据与终端界面的实时同步；通过双通道会话架构，支持用户和服务提供者两种视角的无缝切换；通过三层数据覆盖机制，确保预览数据的灵活性和优先级控制；通过 Mock Token 检测机制，保证预览模式下的数据隔离安全。本发明显著提升了管理后台的配置效率和用户体验，减少了开发测试成本。

**关键词**：终端预览、多角色视角、双通道会话、实时同步、管理后台
