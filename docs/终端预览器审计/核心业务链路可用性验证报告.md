> 说明：本节记录 **“小程序运行真实 @terminal-preview 入口”** 时的阻塞问题。仅允许通过 `miniapp-shell` 构建配置（alias / resolve / webpackChain）解决；不修改 `terminal-preview` 业务代码。

#### I-01：误打入 `react-dom` 导致运行崩溃（已修复 ✅）

- **现象（修复前）**：
  - `TypeError: Right-hand side of 'instanceof' is not an object`
  - `Minified React error #327`
  - 首屏白屏
- **原因（证据级结论）**：
  - 小程序产物中出现 `react-dom` 相关模块（由 `@tarojs/plugin-framework-react` 的引入链路 + 错误 alias 触发），在小程序无 `window/document` 环境下导致崩溃。
- **修复（宿主构建配置）**：
  - 移除 `miniapp-shell/config/index.ts` 中对 `react-dom` 的 alias，确保小程序使用 `@tarojs/react`（react-reconciler）渲染器。

#### I-02：React Query Context 丢失（进行中 🔴）

- **现象**：
  - `Error: No QueryClient set, use QueryClientProvider to set one`
- **业务侧最早调用点（源码）**：
  - `src/components/terminal-preview/index.tsx`：`useQueryClient()`（组件 render 初期）
- **已确认事实**：
  - `pages/main/index` 已在页面组件内包裹 `QueryClientProvider`（构建产物可见 Provider 结构）。
  - 该错误通常意味着 **Provider 与 useQueryClient 来自不同 react-query 实例** 或 **React 实例/模块隔离导致 Context 不可见**。
- **当前处理方向（仅宿主层）**：
  - 强制 `@tanstack/react-query` / `@tanstack/query-core` 单实例解析（alias 到 `miniapp-shell/node_modules`）
  - 通过 `splitChunks` 聚合 React/ReactQuery 相关模块，避免模块隔离
  - 需要配合微信开发者工具“清缓存并编译”验证生效

```typescript
onClick={async () => {
  if (images.length >= maxImages) {
    const wxBridge = getWxBridge()
    wxBridge.showToast({ title: `最多上传${maxImages}张图片`, icon: 'none' })
    return
  }

  try {
    // 宿主能力对接：通过 WxBridge 选择图片
    const wxBridge = getWxBridge()
    const result = await wxBridge.chooseImage({
      count: maxImages - images.length,
      sourceType: ['album', 'camera'],
      sizeType: ['compressed'],
    })

    // 将选择的图片添加到表单
    if (result.tempFilePaths.length > 0) {
      setCustomFieldValues(prev => ({
        ...prev,
        [field.id]: [...images, ...result.tempFilePaths]
      }))
    }
  } catch (err) {
    // 用户取消选择，不做处理
    console.log('[CreateOrderPage] 用户取消选择图片', err)
  }
}}
```

**修改内容**：
- 将模拟图片数据替换为 `wxBridge.chooseImage()` 调用

## 附录 B：小程序组件适配阻塞说明

### 当前状态

小程序宿主壳工程已就绪，环境检测正常：
- ✅ 运行环境检测正常
- ✅ WxBridge 已注入
- ✅ 平台适配层已完成（platformRequest、platformStorage）
- ⏳ 终端预览器组件适配中

### 阻塞原因

终端预览器使用了以下 Web 特有的组件库，无法直接在小程序中运行：

| 组件库 | 用途 | 小程序兼容性 |
|-------|------|-------------|
| shadcn/ui | UI 组件库 | ❌ 依赖 DOM API |
| @radix-ui | Headless 组件 | ❌ 依赖 DOM API |
| lucide-react | 图标库 | ⚠️ 需要适配 |
| tailwindcss | 样式框架 | ⚠️ 需要配置 |

### 解决方案

需要采用**UI 层分离**策略：

```
终端预览器架构
├── 业务逻辑层（保持不变）
│   ├── hooks/          # 状态管理、数据获取
│   ├── api.ts          # API 调用
│   ├── types.ts        # 类型定义
│   └── session.ts      # 会话管理
│
├── UI 组件层（需要适配）
│   ├── components/web/     # Web 版（shadcn/ui）
│   └── components/miniapp/ # 小程序版（@tarojs/components）
│
└── 平台适配层（已完成）
    ├── platform/request    # 请求适配
    ├── platform/storage    # 存储适配
    └── bridge/             # WxBridge
```

### 下一步行动

1. **创建小程序版 UI 组件库**
   - 基于 `@tarojs/components` 实现
   - 保持与 Web 版相同的 Props 接口
   - 使用条件编译或运行时判断切换

2. **逐页面迁移**
   - 优先迁移首页（HomePage）
   - 然后迁移核心链路页面
   - 最后迁移其他页面

3. **保持业务逻辑不变**
   - hooks、api、types 等业务逻辑层保持共用
   - 仅 UI 组件层需要适配
