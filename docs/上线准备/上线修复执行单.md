# 上线修复执行单（修订版）

## 1. 目标与范围

- 目标：在不引入新功能的前提下，完成上线前安全加固与质量门禁，消除 P0/P1 风险。
- 范围：`server`（鉴权、支付、配置、测试接口、密钥治理）、`website`（XSS 渲染链路）、工程质量门禁（lint/build/test）。

## 2. 优先级

### P0（阻断上线，必须先修）

1. 密钥治理（证书/私钥泄露）：立即轮换并从仓库移除敏感密钥资产。
2. 管理员权限守卫修复：`AdminGuard` 禁止“已登录即放行”。
3. 管理接口鉴权统一：`admin/*` 全量收敛到 `AdminGuard`。
4. 配置中心鉴权（资金链路）：封闭 `config` 的支付/短信等写接口。
5. 支付回调验签与幂等：补齐验签、金额校验、商户校验、幂等保护。
6. 下线测试模块：生产不加载 `TestModule` 与 `test/*` 接口。

### P1（P0 完成后立即执行）

1. CMS 设置接口分级鉴权：`public` 只读保留，其余接口收敛至管理员。
2. 前台富文本 XSS 治理：统一使用 `SafeHTML`，禁用裸 `dangerouslySetInnerHTML`。
3. CORS 收敛：`origin: true` 改白名单，禁止任意源携带凭据。
4. `mock-pay` 二次加固：管理员守卫 + 环境开关双保险。
5. 数据库密码治理：替换弱口令，改为强随机密码并完成部署同步。

### P2（质量与可运维）

1. 修复 lint/build 阻断项并建立可持续基线。
2. 修复 server ESLint 版本冲突（避免 8/9 混用）。
3. 补齐关键链路 e2e（鉴权、支付、配置高危写口）。

## 3. 执行顺序

| 时间 | 内容 | 理由 |
|---|---|---|
| Day 1 上午 | 密钥轮换 + AdminGuard 修复 | 先堵住最致命漏洞 |
| Day 1 下午 | 管理接口鉴权统一 + Config/CMS 鉴权 | 关闭无鉴权写入口 |
| Day 2 | TestModule 下线 + 支付验签幂等 | 清理测试接口 + 加固支付 |
| Day 3 | XSS + CORS + mock-pay | P1 安全加固 |
| Day 4 | lint/build + e2e | 质量保障 |
| Day 5 | 回归 + 灰度发布 | 上线前最终确认 |
