### ✅ 问题 1：工作台页面未统一使用 `PermissionPrompt` 组件 【已修复】

**设计规范**（DEV_NOTES.md）:

> 分销中心/**工作台**所有私域页，非 escort 视角 **必须** 返回同一个 `<PermissionPrompt />`，**不允许每个页面自己写 Alert 或 Card**。

**实际情况**:

| 页面 | 是否使用 PermissionPrompt | 状态 |
|------|-------------------------|------|
| `WorkbenchPage.tsx` | ❌ 自己写的权限提示 | 🔴 违规 |
| `OrdersPoolPage.tsx` | ❌ 自己写的权限提示 | 🔴 违规 |
| `OrderDetailPage.tsx` | ❌ 自己写的权限提示 | 🔴 违规 |
| `WorkbenchEarningsPage.tsx` | ❌ 自己写的权限提示 | 🔴 违规 |
| `WorkbenchWithdrawPage.tsx` | ❌ 自己写的权限提示 | 🔴 违规 |
| `WorkbenchSettingsPage.tsx` | ✅ 正确使用 | ✅ |

**修复前差距**: 工作台 6 个页面中仅 1 个使用了统一的 `PermissionPrompt` 组件，其余 5 个各自实现了相似但不完全一致的权限提示 UI。

**✅ 修复后状态**: 工作台 **8/8** 页面（含 2 个旧版页面）全部使用统一的 `PermissionPrompt` 组件。

**代码示例**（违规实现 - WorkbenchPage.tsx）:

```tsx
// ❌ 自己写的权限提示
if (!isEscort) {
  return (
    <div className="flex-1 flex flex-col items-center justify-center px-4">
      <div className="text-5xl mb-4">🔒</div>
      <div className="text-base font-medium text-center">需要陪诊员身份</div>
      <div className="text-sm text-center mt-2">
        请先通过 DebugPanel 注入 escortToken...
      </div>
    </div>
  )
}
```

**正确实现**（WorkbenchSettingsPage.tsx）:

```tsx
// ✅ 使用统一的 PermissionPrompt 组件
import { PermissionPrompt } from '../../PermissionPrompt'

  return (
    <PermissionPrompt
      title="需要陪诊员身份"
```

### P3-TECH-001: PermissionPrompt 回调命名统一

```yaml
优先级: P3（低）
类型: 技术债 / 代码规范
状态: 📋 待处理

影响范围: 
  - src/components/terminal-preview/components/PermissionPrompt.tsx
  - src/components/terminal-preview/components/pages/distribution/*.tsx (5)
  - src/components/terminal-preview/components/pages/workbench/*.tsx (8)

当前状态:
  - 分销中心页面 Props: onLoginClick
  - 工作台页面 Props: onShowLoginDialog
  - 组件内部 Props: onLogin

问题描述:
  - 跨模块命名不一致（onLoginClick vs onShowLoginDialog）
  - 语义略有歧义（动作导向 vs 效果导向）

建议目标:
  - 页面 Props 统一为: onRequestLogin（意图导向）
  - 组件 Props 保持: onLogin

不立即重构的理由:
  1. 现状可接受：模块内已保持一致
  2. 无功能影响：仅命名差异，不影响运行时行为
  3. 重构成本较高：涉及 13 个页面 + 组件定义

触发时机:
  - 下次涉及 PermissionPrompt 的功能迭代时顺带重构
  - 或统一处理"登录流程"相关需求时

预估工时: 0.5h
```
