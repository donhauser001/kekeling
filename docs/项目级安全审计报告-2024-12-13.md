## 二、🔴 Critical 级问题（必须立刻阻断）

### 2.1 前端 XSS 注入面过大

**风险等级**：🔴 Critical

**发现的注入点**（5 处）：

| # | 文件 | 模式 |
|---|------|------|
| 1 | `operation-guides-detail-sheet.tsx:98` | `dangerouslySetInnerHTML={{ __html: item.content }}` |
| 2 | `ServiceDetailPage.tsx:666` | `dangerouslySetInnerHTML={{ __html: service.content }}` |
| 3 | `ContentSection.tsx:28` | `dangerouslySetInnerHTML={{ __html: homeSettings.content.code }}` |
| 4 | `rich-editor/index.tsx:106` | `editorRef.current.innerHTML = value` |
| 5 | `rich-editor/index.tsx:125` | `editorRef.current.innerHTML = ''` |

**风险判定**：
- 一旦 XSS 成功，结合当前 token 存储方式（localStorage），攻击者可直接窃取会话凭证
- 可导致：token 被窃取、越权操作（以管理员身份发起 API 调用）、内网探测

**整改门槛**：

| 要求 | 说明 |
|------|------|
| SafeHTML 组件 | 建立统一的 `SafeHTML` 组件，内部强制 DOMPurify 净化 |
| 白名单标签 | 只允许 `p, br, strong, em, ul, ol, li, h1-h3, a, img` |
| 禁止属性 | 禁止 `style, on*, iframe, svg, math` |
| ESLint 规则 | 禁止直接使用 `dangerouslySetInnerHTML` |

**验收标准**：
- [ ] 全仓搜索 `dangerouslySetInnerHTML` 只出现在 `SafeHTML` 组件内
- [ ] ESLint `react/no-danger` 规则生效
- [ ] CSP `script-src 'self'` 配置生效

### 2.2 生产 docker-compose.yml 默认配置

**文件**：`docker-compose.yml`

**发现的高危默认值**：

```yaml
POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-kekeling123}
JWT_SECRET: ${JWT_SECRET:-kekeling-jwt-secret-key-production-2024}
ports:
  - "${POSTGRES_PORT:-5436}:5432"  # DB 端口暴露
  - "${ADMINER_PORT:-8080}:8080"   # Adminer 暴露
```

**验收标准**：
- [ ] docker-compose.yml 中无任何默认口令/密钥
- [ ] 生产环境 DB 端口不暴露到宿主机
- [ ] Adminer 生产环境不启用

### 2.3 JWT 密钥硬编码（代码层面）

**文件**: `server/src/modules/auth/strategies/jwt.strategy.ts:16`

```typescript
// ❌ 当前代码 - 存在默认密钥
secretOrKey: configService.get('JWT_SECRET') || 'kekeling-secret-key',
```

**典型后果**：一旦密钥泄露或被猜到，攻击者可伪造任意身份 token，直接变成"全系统后门"。

#### 整改门槛（最低要求）

| 要求 | 说明 |
|------|------|
| 密钥来源 | 必须来自环境变量或密钥管理服务（KMS/Secrets Manager） |
| 禁止默认值 | 禁止任何形式硬编码与默认值回退 |
| 密钥轮转 | 上线/测试/开发环境都要换（曾提交到仓库的密钥视为已泄露） |

#### 修复代码

```typescript
// ✅ 修复方案 - 缺失时直接报错阻止启动
const jwtSecret = configService.get('JWT_SECRET');
if (!jwtSecret) {
  throw new Error('JWT_SECRET environment variable is required');
}
// ...
secretOrKey: jwtSecret,
```

#### 验收标准

- [ ] 仓库全局搜索不到 `JWT_SECRET` / `secret` 常量明文
- [ ] 线上旧 token 全部失效（强制 re-login）
- [ ] 缺失环境变量时应用启动失败（而非使用默认值）
- [ ] 新密钥长度 ≥ 32 字符，随机生成

## 三、🟠 High 级问题（必须上线前修复）

### 3.1 文件上传接口无鉴权

**文件**: `server/src/modules/upload/upload.controller.ts`

**典型后果**：未授权上传、任意文件写入、恶意脚本/木马载荷、对象存储刷量、间接 RCE

#### 整改门槛（最低要求）

| 要求 | 说明 |
|------|------|
| 鉴权 | 上传必须带鉴权（userToken/escortToken 分域） |
| RBAC/ABAC | 谁能上传到哪个业务对象 |
| 文件校验 | 类型白名单 + MIME sniff + 大小限制 + 频率限制 |
| 最佳实践 | 对象存储采用短期预签名直传优于后端中转 |

#### 修复代码

```typescript
import { UseGuards } from '@nestjs/common';
import { JwtAuthGuard } from '../auth/guards/jwt-auth.guard';

@ApiTags('上传')
@Controller('upload')
@UseGuards(JwtAuthGuard)  // ✅ 添加鉴权
export class UploadController {
  @Post()
  @UseInterceptors(FileInterceptor('file', {
    fileFilter: (req, file, cb) => {
      // ✅ 添加 MIME 类型校验
      const allowedMimes = ['image/jpeg', 'image/png', 'image/gif', 'image/webp'];
      if (allowedMimes.includes(file.mimetype)) {
        cb(null, true);
      } else {
        cb(new BadRequestException('不支持的文件类型'), false);
      }
    },
    limits: { fileSize: 5 * 1024 * 1024 }  // ✅ 限制文件大小 5MB
  }))
  async upload(...) { }
}
```

#### 验收标准

- [ ] 未携带合法 token 的上传请求一律 401/403
- [ ] 上传记录可追溯到 userId/escortId、业务对象、IP、UA
- [ ] MIME sniff 校验生效（改扩展名无法绕过）
- [ ] 文件大小限制生效

### 3.2 支付接口 Mock 代码残留

**文件**: `server/src/modules/payment/payment.service.ts`

**典型后果**：绕过真实支付校验、伪造成功回调、产生"0 元购"，属于直接财务风险

#### 整改门槛（最低要求）

| 要求 | 说明 |
|------|------|
| Mock 隔离 | mock 支付逻辑只能存在于 `__tests__` 或明确的 dev-only 路径 |
| 环境变量控制 | 生产编译时剔除 mock 分支（环境变量强制关闭） |
| 状态推进规则 | 订单状态只能由服务端基于支付网关回调签名验证后推进 |
| 客户端不可信 | 不接受客户端"支付成功"通知作为事实来源 |

```typescript
// ❌ 当前代码 - payment.service.ts:206
// TODO: 实际项目中需要调用微信支付统一下单接口
// 这里返回模拟数据，方便开发测试
```

#### 验收标准

- [ ] 生产环境构建产物中不存在 mock 支付分支（可通过 grep/构建产物扫描验证）
- [ ] 接入真实支付 SDK（如 `wechatpay-node-v3`）
- [ ] 支付回调验证签名后才更新订单状态

### 3.3 CI/CD 缺失测试环节

**文件**: `.github/workflows/ci.yml`

**典型后果**：代码提交后未运行单元测试或集成测试，重大业务逻辑的破坏性变更无法被拦截

#### 修复建议

```yaml
# 在 ci.yml 中添加
- name: Run backend tests
  run: cd server && pnpm test

- name: Run backend e2e tests
  run: cd server && pnpm test:e2e

- name: Run security access control tests
  run: cd server && pnpm test:e2e -- --grep "access-control"
```

#### 验收标准

- [ ] CI 流水线包含单元测试步骤
- [ ] CI 流水线包含 e2e 测试步骤
- [ ] 安全相关测试（API 访问控制）接入 CI

## 四、Medium 级问题 (P2 长期优化)

### 4.1 Server TypeScript 严格度不足 🟡

**文件**: `server/tsconfig.json`

**现状**：

```json
{
  "compilerOptions": {
    "noImplicitAny": false,      // ❌ 允许隐式 any
    "strictBindCallApply": false, // ❌ 未开启
    // 缺少 "strict": true
  }
}
```

**风险**：允许隐式 `any` 会导致类型系统失效，增加运行时错误风险。

**修复建议**：逐步开启严格模式并修复类型错误。

### 4.2 Monorepo 结构不规范 🟡

**现状**：
- 根目录 `package.json` 是 Admin 前端
- `server/` 和 `miniapp/` 各有独立的 `pnpm-lock.yaml`
- 不是真正的 pnpm workspace 管理

**风险**：依赖版本不一致，CI/CD 缓存效率低。

**建议**：考虑重构为标准 Monorepo 结构。

## 七、API 访问控制安全测试用例

> 建议接入 CI，作为上线门禁

```typescript
// e2e/access-control.spec.ts
import * as request from 'supertest';

describe('API 访问控制', () => {
  describe('escort 路径 /api/escort-app/**', () => {
    it('无 token 应返回 401', async () => {
      const res = await request(app).get('/api/escort-app/workbench/stats');
      expect(res.status).toBe(401);
    });
    
    it('userToken 应返回 403', async () => {
      const res = await request(app)
        .get('/api/escort-app/workbench/stats')
        .set('Authorization', `Bearer ${userToken}`);
      expect(res.status).toBe(403);
    });
    
    it('escortToken 应返回 200', async () => {
      const res = await request(app)
        .get('/api/escort-app/workbench/stats')
        .set('Authorization', `Bearer ${escortToken}`);
      expect(res.status).toBe(200);
    });
  });
  
  describe('上传接口 /api/upload', () => {
    it('无 token 应返回 401', async () => {
      const res = await request(app)
        .post('/api/upload')
        .attach('file', Buffer.from('test'), 'test.png');
      expect(res.status).toBe(401);
    });
  });
  
  describe('Session 联动失效', () => {
    it('userToken 注销后，escortToken 应失效', async () => {
      // 1. 用户登录，获取 userToken
      // 2. 陪诊员登录，获取 escortToken  
      // 3. 用户注销（使 userToken 失效）
      // 4. 用 escortToken 访问 escort 接口
      // 5. 期望返回 401
    });
  });
});
```
