# 小程序页面改造规范

> 本规范基于 terminal-preview 组件库跨平台适配实践总结，适用于所有在小程序中渲染的页面组件。

---

## 一、核心原则

```
样式双写 + 图标用 iconfont + 禁止 <style> 标签
```

---

## 二、十三条硬性规则

### 规则 1：布局属性必须在 style 中定义

小程序不识别 Tailwind className，以下属性**必须**在 style 中完整表达：

| 类别 | 必须在 style 中的属性 |
|------|----------------------|
| Flex | `display`, `flexDirection`, `alignItems`, `justifyContent`, `gap`, `flex`, `flexWrap`, `flexShrink` |
| Grid | `display: 'grid'`, `gridTemplateColumns`, `gridGap` |
| 定位 | `position`, `top`, `right`, `bottom`, `left`, `zIndex` |
| 尺寸 | `width`, `height`, `minWidth`, `minHeight`, `maxWidth`, `maxHeight` |
| 溢出 | `overflow`, `overflowX`, `overflowY` |

```tsx
// ❌ 错误 - 仅靠 className 实现布局
<Box className='flex items-center gap-2'>

// ✅ 正确 - style 为准，className 仅作 Web 视觉辅助
<Box
  className='flex items-center gap-2'  // Web-only，可选保留
  style={{
    display: 'flex',
    alignItems: 'center',
    gap: 8 * wxScale,
  }}
>
```

> ⚠️ **重要**：`style` 是唯一真相源，`className` 仅作为 Web 端的视觉辅助（便于开发时预览），**不保证小程序端生效**。

---

### 规则 2：className 仅作 Web 辅助，禁止作为布局唯一来源

**核心原则：style 为准，className 为辅。**

**允许单独使用 className**（非布局、非关键样式）：
- `text-sm`, `font-medium`, `rounded-lg`, `transition-all`, `cursor-pointer`

**禁止单独使用 className**（布局关键词，必须在 style 中有等效定义）：
- `flex`, `grid`, `block`, `hidden`, `inline-flex`
- `items-*`, `justify-*`, `gap-*`, `flex-*`
- `w-*`, `h-*`, `p-*`, `m-*`, `min-*`, `max-*`
- `absolute`, `relative`, `fixed`, `sticky`, `top-*`, `left-*`, `right-*`, `bottom-*`
- `overflow-*`, `z-*`

> 💡 **建议**：如果团队执行力不足，可采用更严格策略——**布局类一律禁止写进 className**，从源头杜绝误用。

### 规则 3：wxScale 只用于视觉尺寸

**wxScale 是平台级常量，必须集中定义，禁止页面私自修改数值。**

```tsx
// ✅ 从统一模块导入（推荐）
import { wxScale } from '../../platform/scale'

// 或在组件顶部计算（现状）
const wxScale = isWxEnvironment() ? 1.1 : 1
```

| 必须乘 wxScale | 禁止乘 wxScale |
|---------------|---------------|
| `fontSize` | `flex: 1` |
| `padding`, `margin`, `gap` | `display`, `flexDirection` |
| `borderRadius` | `alignItems`, `justifyContent` |
| `width`, `height`（固定像素值） | 百分比值如 `'100%'` |
| `lineHeight`（像素值） | `zIndex`, `opacity` |

```tsx
// ✅ 正确
style={{
  flex: 1,                    // 不乘
  fontSize: 14 * wxScale,     // 乘
  gap: 8 * wxScale,           // 乘
}}
```

#### 3.1 边缘案例：1px 物理边框（Hairline）

在视网膜屏幕（Retina）上，`1 * wxScale` 会变成 `1.1px`，可能导致边框消失或变粗。

```tsx
// ❌ 错误 - 1px 边框乘 scale 后可能异常
borderWidth: 1 * wxScale,  // = 1.1px，显示不稳定

// ✅ 正确 - 细分割线固定为 1px
borderWidth: 1,  // 不乘 scale
borderBottomWidth: 1,

// ✅ 或使用 hairline 常量
const hairline = 1  // 物理 1px，专用于细线
borderWidth: hairline,
```

| 场景 | 处理方式 |
|------|----------|
| 细分割线、列表分隔线 | 固定 `1px`，**不乘** wxScale |
| 卡片边框、输入框边框 | 固定 `1px`，**不乘** wxScale |
| 粗边框（2px 及以上） | 可乘 wxScale |

> ⚠️ **统一管理**：wxScale 值（当前为 1.1）是基于 iPhone 主流机型调优的经验值。如未来需按机型/屏幕密度分层，应在 `platform/scale.ts` 统一升级策略，**禁止在业务代码中硬编码不同数值**。

### 规则 4：数据获取用 useState + useEffect

React Query 的 `useQuery` 在小程序中存在兼容性问题。

```tsx
// ❌ 错误
const { data } = useQuery({
  queryKey: ['services'],
  queryFn: () => api.getServices(),
})

// ✅ 正确
const [services, setServices] = useState([])
const [loading, setLoading] = useState(true)

useEffect(() => {
  api.getServices()
    .then(result => setServices(result.data || []))
    .catch(console.error)
    .finally(() => setLoading(false))
}, [])
```

#### 4.1 首屏闪烁处理（骨架屏）

**小程序中 `useEffect` 触发时机略晚于首屏渲染**，如果不处理加载状态，页面会先展示"空白/默认值"再跳变到真实数据，体验很差。

```tsx
// ✅ 推荐：显式处理 loading 状态
const [services, setServices] = useState<Service[]>([])
const [loading, setLoading] = useState(true)

useEffect(() => {
  api.getServices()
    .then(result => setServices(result.data || []))
    .finally(() => setLoading(false))
}, [])

// 渲染时
if (loading) {
  return <ServiceListSkeleton />  // 骨架屏
}

if (services.length === 0) {
  return <EmptyState message="暂无服务" />
}

return <ServiceList data={services} />
```

**骨架屏设计要点：**

| 要点 | 说明 |
|------|------|
| 布局一致 | 骨架屏布局应与真实内容完全一致，避免跳变 |
| 动画轻量 | 使用渐变动画（shimmer），不要用复杂动画 |
| 高度固定 | 骨架屏高度应与真实内容接近，避免页面抖动 |

```tsx
// 骨架屏示例
function ServiceListSkeleton() {
  return (
    <Box style={{ padding: 12 * wxScale }}>
      {[1, 2, 3].map(i => (
        <Box
          key={i}
          style={{
            height: 80 * wxScale,
            marginBottom: 12 * wxScale,
            backgroundColor: '#f3f4f6',
            borderRadius: 8 * wxScale,
          }}
        />
      ))}
    </Box>
  )
}
```

### 规则 5：图标用 size 和 color props

`lucide-compat` 图标通过 `style.width/height` 设置尺寸**无效**。

```tsx
// ❌ 错误
<Star style={{ width: 12, height: 12, color: '#fbbf24' }} />

// ✅ 正确
<Star size={12 * wxScale} color="#fbbf24" />
```

---

### 规则 6：禁止使用 `<style>` 标签

小程序不支持内联 `<style>` 标签。

```tsx
// ❌ 错误
<style>{`.my-class { display: none; }`}</style>

// ✅ 正确（Web 环境条件渲染）
{isBrowserEnvironment() && (
  <style>{`.my-class { display: none; }`}</style>
)}

// ✅ 推荐（全局样式放 app.scss）
```

---

### 规则 7：圆形按钮用 Box + 固定宽高

小程序 Button 有默认样式，会导致圆形变椭圆。

```tsx
// ❌ 错误
<Button style={{ padding: 4, borderRadius: 9999 }}>
  <Heart size={12} />
</Button>

// ✅ 正确
<Box
  onClick={handleClick}
  style={{
    width: 22,
    height: 22,
    borderRadius: 11,  // 半径 = 宽度/2
    display: 'flex',
    alignItems: 'center',
    justifyContent: 'center',
  }}
>
  <Heart size={12} color="#fff" />
</Box>
```

### 规则 8：主操作按钮内边距标准

小程序中按钮的默认行高与 Web 不同，需要单独设置内边距以保持视觉一致。

```tsx
// ✅ 正确 - 主操作按钮（如"立即预约"、"提交"等）
<Button
  style={{
    flex: 1,
    paddingTop: isWxEnvironment() ? 14 * wxScale : 10,
    paddingBottom: isWxEnvironment() ? 14 * wxScale : 10,
    borderRadius: 9999,
    fontSize: 14 * wxScale,
    fontWeight: 500,
    backgroundColor: primaryColor,
    color: '#fff',
  }}
>
  立即预约
</Button>
```

| 环境 | 上下内边距 | 说明 |
|------|-----------|------|
| Web 预览器 | `10px` | 保持默认样式 |
| 小程序 | `14 * wxScale` ≈ 16px | 补偿小程序 Text 行高差异 |

**原因**：小程序中 `Button` 组件内部的 `Text` 组件行高与 Web 不同，导致按钮高度偏小。通过增加小程序端的内边距来对齐视觉效果。

### 规则 9：统一使用 iconfont 图标系统

**最终口径（不可误解）：三端底层统一使用 iconfont 字体图标。`lucide-compat` 是 iconfont 的映射桥，不是独立图标系统。**

管理后台、终端预览器、小程序三端统一使用 **iconfont 字体图标**（共 775 个图标）。

#### 9.1 架构说明

```
┌─────────────────────────────────────────────────────────────┐
│  业务代码                                                    │
│  ┌─────────────────────┐    ┌─────────────────────┐        │
│  │ terminal-preview    │    │ miniapp-shell       │        │
│  │ import { Star }     │    │ import Icon         │        │
│  │ from 'lucide-compat'│    │ from '@/components' │        │
│  └─────────┬───────────┘    └─────────┬───────────┘        │
│            │                          │                     │
│            ▼                          ▼                     │
│  ┌─────────────────────────────────────────────────┐       │
│  │           iconfont 字体图标（唯一真相源）          │       │
│  │           775 个图标，三端一致渲染               │       │
│  └─────────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────────┘
```

#### 9.2 使用方式

```tsx
// ✅ terminal-preview 中：使用 lucide-compat（内部映射到 iconfont）
import { Star, Heart, Phone } from '../../ui/lucide-compat'

<Star size={16 * wxScale} color="#fbbf24" />
<Heart size={20 * wxScale} color="#ef4444" />

// ✅ miniapp-shell 原生页面中：直接使用 Icon 组件
import Icon from '@/components/Icon'

<Icon name="star" size={16} color="#fbbf24" />
<Icon name="heart" size={20} color="#ef4444" />
```

> 💡 **lucide-compat 本质**：它是"同名到 iconfont 的桥"，在 Web 端渲染 iconfont 字体，在小程序端同样渲染 iconfont。**禁止**将其理解为"terminal-preview 用 lucide，小程序用 iconfont"。

#### 9.3 禁止事项

| 禁止 | 说明 |
|------|------|
| ❌ emoji | 不要用 🏠 ⭐ ❤️ 等 emoji |
| ❌ Unicode 符号 | 不要用 ✓ ★ → ✕ 等符号 |
| ❌ 内联 SVG | 影响三端一致性 |
| ❌ style.width/height | 图标尺寸必须用 `size` prop |
| ❌ 直接 import lucide-react | 必须用 lucide-compat 兼容层 |

#### 9.4 尺寸规范

| 使用场景 | size 值 |
|----------|---------|
| 按钮内图标 | 16-18 * wxScale |
| 列表项图标 | 20-24 * wxScale |
| 标题图标 | 24-32 * wxScale |
| 大型展示 | 48-64 * wxScale |

|------|--------|

### 规则 10：文本块需设置 display: block 和行距

小程序中 `Text` 组件默认是内联元素，多个 `Text` 会显示在同一行。需要显式设置块级显示和行距。

```tsx
// ❌ 错误 - 标题和描述可能显示在同一行
<Text style={{ fontSize: 18 * wxScale }}>服务名称</Text>
<Text style={{ marginTop: 8 * wxScale }}>服务描述</Text>

// ✅ 正确 - 显式设置 display: block 和行距
<Text
  style={{
    display: 'block',
    fontSize: 18 * wxScale,
    fontWeight: 700,
  }}
>
  服务名称
</Text>
<Text
  style={{
    display: 'block',
    marginTop: isWxEnvironment() ? 12 * wxScale : 8,
    fontSize: 14 * wxScale,
    lineHeight: 1.5,
  }}
>
  服务描述
</Text>
```

| 场景 | 行距 (lineHeight) | 上边距 (marginTop) |
|------|-------------------|-------------------|
| 标题后描述 | 1.5 | 小程序 `12*wxScale`，Web `8` |
| 段落文本 | 1.6 | - |
| 列表项 | 1.4 | - |

### 规则 11：小程序头部安全区域与返回按钮规范

#### 11.1 小程序头部参数

小程序顶部有状态栏和胶囊按钮，需要正确预留空间。

**⚠️ 重要：优先从运行时 API 读取，常量仅作兜底默认值。**

```tsx
// ✅ 推荐：运行时读取（精确适配各机型）
import { getSystemInfoSync, getMenuButtonBoundingClientRect } from '@tarojs/taro'

function getHeaderParams() {
  try {
    const systemInfo = getSystemInfoSync()
    const menuButton = getMenuButtonBoundingClientRect()
    
    return {
      statusBarHeight: systemInfo.statusBarHeight || 44,
      capsuleTop: menuButton.top - (systemInfo.statusBarHeight || 44),
      capsuleHeight: menuButton.height || 32,
      capsuleWidth: menuButton.width || 87,
      capsuleRight: systemInfo.windowWidth - menuButton.right,
    }
  } catch (e) {
    // 兜底默认值（基于 iPhone X）
    return {
      statusBarHeight: 44,
      capsuleTop: 6,
      capsuleHeight: 32,
      capsuleWidth: 87,
      capsuleRight: 7,
    }
  }
}

// ⚠️ 兜底常量（仅在 API 读取失败时使用）
const DEFAULT_STATUS_BAR_HEIGHT = 44
const DEFAULT_CAPSULE_TOP = 6
const DEFAULT_CAPSULE_HEIGHT = 32
```

> 💡 **为什么不能硬编码**：不同机型（Android、非刘海 iPhone、iPad）的状态栏高度和胶囊位置不同，硬编码 44px 在部分机型上会出现错位。

#### 11.2 页面顶部导航栏

页面顶部导航栏需要预留状态栏安全区域：

```tsx
const wxSafeAreaTop = isWxEnvironment() ? 44 : 0

// 顶部导航栏
<Box
  style={{
    position: 'sticky',
    top: 0,
    zIndex: 20,
    paddingTop: wxSafeAreaTop + 12 * wxScale,  // 预留状态栏空间
    paddingBottom: 12 * wxScale,
    backgroundColor: colors.headerBg,
  }}
>
  <Text>页面标题</Text>
</Box>
```

#### 11.3 悬浮返回按钮（与胶囊对齐）

详情页使用固定悬浮的圆形返回按钮，**垂直居中对齐小程序右上角胶囊按钮**：

```tsx
import { Box, Icon } from '../../ui/primitives'
import { isWxEnvironment } from '../../platform/env'

const wxScale = isWxEnvironment() ? 1.1 : 1

// 小程序胶囊按钮位置参数
const wxStatusBarHeight = 44
const wxCapsuleTop = 6
const wxCapsuleHeight = 32

export function HeaderButton({ isDarkMode, onBack }) {
  const buttonSize = 36 * wxScale

  // 计算返回按钮的 top 值，使其与胶囊按钮垂直居中对齐
  // 胶囊中心 = 状态栏高度 + 胶囊距顶部 + 胶囊高度/2 = 44 + 6 + 16 = 66px
  const capsuleCenter = wxStatusBarHeight + wxCapsuleTop + wxCapsuleHeight / 2
  const buttonTop = isWxEnvironment() ? capsuleCenter - buttonSize / 2 : 12

  return (
    <Box
      onClick={onBack}
      style={{
        position: 'fixed',
        top: buttonTop,
        left: 12 * wxScale,
        zIndex: 50,
        width: buttonSize,
        height: buttonSize,
        borderRadius: buttonSize / 2,
        display: 'flex',
        alignItems: 'center',
        justifyContent: 'center',
        backgroundColor: isDarkMode ? 'rgba(0, 0, 0, 0.4)' : 'rgba(255, 255, 255, 0.7)',
        boxShadow: '0 2px 8px rgba(0, 0, 0, 0.15)',
      }}
    >
      <Icon name="left" size={20 * wxScale} color={isDarkMode ? '#fff' : '#333'} />
    </Box>
  )
}
```

**设计规范：**

| 属性 | 值 | 说明 |
|------|-----|------|
| 定位 | `fixed` | 固定悬浮，滚动时始终可见 |
| 顶部距离 | 与胶囊垂直居中对齐（约 46px） | 小程序；Web 为 12px |
| 尺寸 | `36 * wxScale` | 适中的点击区域 |
| 圆角 | `buttonSize / 2` | 正圆形 |
| 背景 | 半透明白色/黑色 | 70%/40% 不透明度 |
| 阴影 | 轻微投影 | 提升层次感 |
| 图标 | `left` | iconfont 左箭头图标 |
| z-index | `50` | 确保在最上层 |

**注意事项：**
- 小程序不支持 `backdrop-filter` 毛玻璃效果，使用纯半透明背景
- 右侧收藏/分享按钮在小程序中隐藏，使用原生胶囊按钮功能
- 返回按钮需与胶囊按钮**水平居中对齐**，提升视觉一致性
- 页面顶部导航栏需预留 `wxSafeAreaTop`（44px）避开刘海和状态栏

### 规则 12：大文件先拆分再改造

**满足以下任一条件，必须先进行模块化拆分，然后再进行规范改造：**

| 触发条件 | 说明 |
|----------|------|
| 超过 **500 行** | 纯行数判定 |
| 包含 **>3 个 modal/selector** | 弹窗/选择器过多 |
| 包含 **>2 个数据请求与交互流** | 业务逻辑复杂 |
| 包含 **>1 个可复用区块** | 如独立卡片、底栏、表单段 |

#### 12.1 拆分步骤

1. **分析文件结构**：识别独立的子组件、工具函数、类型定义
2. **创建目录结构**：
   ```
   pages/
   └── create-order/
       ├── index.tsx              # 主组件（入口）
       ├── types.ts               # 类型定义
       ├── hooks.ts               # 自定义 hooks
       └── components/
           ├── index.ts           # 组件导出
           ├── ServiceCard.tsx    # 服务卡片
           ├── FormFields.tsx     # 表单字段
           ├── BottomBar.tsx      # 底部操作栏
           └── modals/
               ├── PatientPicker.tsx
               ├── HospitalPicker.tsx
               └── ...
   ```
3. **提取公共组件**：弹窗、选择器等可复用组件
4. **逐个改造子组件**：按规范改造每个拆分后的文件

#### 12.2 拆分原则

| 原则 | 说明 |
|------|------|
| 单一职责 | 每个组件只做一件事 |
| 100-300 行 | 拆分后每个文件控制在此范围 |
| 保持功能完整 | 拆分不得删减任何功能 |
| 类型独立 | 类型定义放在 `types.ts` |
| hooks 独立 | 自定义逻辑放在 `hooks.ts` |

#### 12.3 示例：ServiceDetailPage 的拆分

```
service-detail/
├── ServiceDetailPage.tsx      # 主组件 (~150行)
├── types.ts                   # 类型定义 (~140行)
├── hooks.ts                   # 自定义 hooks (~50行)
└── components/
    ├── index.ts
    ├── ServiceHeader.tsx      # ~60行
    ├── ServiceImageCarousel.tsx
    ├── ServiceInfoCard.tsx
    ├── ServiceInfoTabs.tsx
    ├── ServiceGuarantees.tsx
    ├── BottomActionBar.tsx
    └── ...（共 12 个子组件）
```

**好处：**
- 改造更可控，每次只处理小文件
- 代码更易维护和测试
- 减少改造出错的风险
- 便于 Code Review

### 规则 13：Image 组件必须显式指定 mode 属性

小程序原生 `Image` 的缩放模式（`mode`）与 Web 的 `object-fit` **不完全等价**，且默认行为不同。**严禁依赖默认缩放模式。**

```tsx
// ❌ 错误 - 未指定 mode，小程序可能显示异常
<Image src={imageUrl} style={{ width: 100, height: 100 }} />

// ✅ 正确 - 显式指定 mode
<Image 
  src={imageUrl} 
  mode="aspectFill"  // 必须显式指定
  style={{ width: 100 * wxScale, height: 100 * wxScale }} 
/>
```

#### 13.1 mode 属性映射

| 小程序 mode | Web object-fit | 说明 |
|-------------|----------------|------|
| `scaleToFill` | `fill` | 拉伸填满，可能变形（默认值，**不推荐**） |
| `aspectFit` | `contain` | 保持比例，完整显示，可能留白 |
| `aspectFill` | `cover` | 保持比例，裁剪填满（**最常用**） |
| `widthFix` | - | 宽度固定，高度自适应（小程序特有） |
| `heightFix` | - | 高度固定，宽度自适应（小程序特有） |

#### 13.2 常见场景推荐

| 场景 | 推荐 mode | 说明 |
|------|-----------|------|
| 头像、缩略图 | `aspectFill` | 裁剪填满，保证不留白 |
| 轮播图、Banner | `aspectFill` | 全屏覆盖 |
| 商品图、列表图 | `aspectFill` | 统一尺寸展示 |
| 文章配图（需完整显示） | `aspectFit` | 保证图片完整 |
| 自适应高度图片 | `widthFix` | 宽度撑满，高度自动计算 |

#### 13.3 跨平台原语实现

```tsx
// ui/primitives/Image.tsx
export function Image({ src, mode = 'aspectFill', style, ...props }) {
  if (isWxEnvironment()) {
    return <TaroImage src={src} mode={mode} style={style} {...props} />
  }
  
  // Web 端映射
  const objectFitMap = {
    scaleToFill: 'fill',
    aspectFit: 'contain',
    aspectFill: 'cover',
    widthFix: 'cover',  // 近似
    heightFix: 'cover', // 近似
  }
  
  return (
    <img 
      src={src} 
      style={{ 
        ...style, 
        objectFit: objectFitMap[mode] || 'cover',
      }} 
      {...props} 
    />
  )
}
```

### 3.3 页面头部规范

#### 3.3.1 头部类型

| 类型 | 使用场景 | 特点 |
|------|----------|------|
| **自定义导航栏** | 普通页面（编辑资料、列表等） | 标题居中，返回按钮左侧，主色背景 |

#### 3.3.2 自定义导航栏（Type A）

适用于需要自定义头部的普通页面（如编辑资料、设置等）：

```tsx
const wxSafeAreaTop = isWxEnvironment() ? getHeaderParams().statusBarHeight : 0
const primaryColor = themeSettings.primaryColor

<Box
  style={{
    position: 'sticky',  // 见下方 sticky 降级说明
    top: 0,
    zIndex: 100,
    backgroundColor: primaryColor,  // 使用主色背景
    paddingTop: wxSafeAreaTop,      // 预留状态栏空间
  }}
>
  <Box
    style={{
      display: 'flex',
      alignItems: 'center',
      justifyContent: 'center',     // 标题居中
      position: 'relative',
      height: 44 * wxScale,
      paddingLeft: 12 * wxScale,
      paddingRight: 12 * wxScale,
    }}
  >
    {/* 返回按钮（绝对定位左侧） */}
    <Box
      onClick={onBack}
      style={{
        position: 'absolute',
        left: 12 * wxScale,
        display: 'flex',
        alignItems: 'center',
        justifyContent: 'center',
        width: 36 * wxScale,
        height: 36 * wxScale,
      }}
    >
      <Icon name="left" size={22 * wxScale} color="#fff" />
    </Box>

    {/* 标题（居中） */}
    <Text style={{ fontSize: 17 * wxScale, fontWeight: 600, color: '#fff' }}>
      页面标题
    </Text>
    
    {/* 右侧区域：留空或放置操作按钮 */}
    {/* 注意：右侧按钮不得超出胶囊按钮左边界 */}
  </Box>

```

**设计规范：**

| 属性 | 值 | 说明 |
|------|-----|------|
| 定位 | `sticky` | 滚动时吸顶 |
| 背景 | `themeSettings.primaryColor` | 主色背景 |
| 状态栏预留 | `paddingTop: 44` | 小程序需预留状态栏 |
| 导航栏高度 | `44 * wxScale` | 与原生导航栏一致 |
| 标题字号 | `17 * wxScale` | 标准导航栏标题大小 |
| 返回按钮 | 绝对定位左侧 | 点击区域 36x36 |
| 右侧操作 | **置于底部或页面内** | 避免与胶囊冲突 |

小程序右上角有胶囊按钮（分享/更多），自定义导航栏的右侧操作按钮会被遮挡。解决方案：

```tsx

<Box style={{ position: 'absolute', right: 12 }}>
  <Text>保存</Text>
</Box>

// ✅ 正确：保存按钮放在页面底部
<Box style={{ marginTop: 24 * wxScale, marginLeft: 12, marginRight: 12 }}>
  <Box
    onClick={handleSave}
    style={{
      height: 48 * wxScale,
      backgroundColor: primaryColor,
      borderRadius: 12 * wxScale,
      display: 'flex',
      alignItems: 'center',
      justifyContent: 'center',

  >
    <Text style={{ color: '#fff', fontSize: 16 * wxScale }}>保存修改</Text>
  </Box>
```

#### 3.3.4 sticky 定位降级方案

在不同小程序运行环境与 Taro 渲染层中，`position: 'sticky'` 的表现可能存在差异（尤其嵌套滚动容器、ScrollView 场景）。

**降级策略：**

```tsx
// 若 sticky 不稳定，使用 fixed + 占位 spacer 降级
<>
  {/* 固定头部 */}
  <Box
    style={{
      position: 'fixed',
      top: 0,
      left: 0,
      right: 0,
      zIndex: 100,
      backgroundColor: primaryColor,
      paddingTop: wxSafeAreaTop,
    }}
  >
    {/* 导航栏内容 */}
  </Box>
  
  {/* 占位 spacer，避免内容被遮挡 */}
  <Box style={{ height: wxSafeAreaTop + 44 * wxScale }} />
</>
```

> 💡 **建议**：封装统一的 `PageHeader` / `SafeAreaHeader` 组件，内部处理 sticky/fixed 降级逻辑，业务代码无需关心。

#### 3.3.5 页面配置文件与动态主题色

**核心结论：动态主题色场景必须使用 `navigationStyle: 'custom'` 自绘导航栏。**

小程序 `index.config.ts` 中的 `navigationBarBackgroundColor` 是**编译期静态值**，而 `themeSettings.primaryColor` 是**运行期动态值**，两者无法同步。

```ts

  navigationBarTitleText: '个人信息',

})
```

| 场景 | 配置方式 |
|------|----------|
| 固定品牌色（不随主题变） | 可用原生 `navigationBarBackgroundColor` |
| 动态主题色 | **必须** `navigationStyle: 'custom'` + 自绘导航栏 |

### 3.4 z-index 层级管理

#### 3.4.1 全局层级常量

**建议在全局定义 `layers.ts` 常量文件，统一管理 z-index 层级，避免层级混乱。**

```tsx
// platform/layers.ts
export const layers = {
  // 基础层
  base: 0,
  
  // 内容层
  content: 10,
  dropdown: 20,
  
  // 导航层
  header: 50,
  tabBar: 50,
  backButton: 50,
  
  // 覆盖层
  overlay: 100,
  modal: 200,
  toast: 300,
  
  // 最高层
  loading: 400,
  systemAlert: 500,
}

// 使用示例
import { layers } from '../../platform/layers'

<Box style={{ zIndex: layers.header }}>导航栏</Box>
<Box style={{ zIndex: layers.modal }}>弹窗</Box>
```

#### 3.4.2 小程序原生组件层级问题

**⚠️ 重要：小程序中 `map`、`video`、`canvas`、`camera` 等原生组件的层级高于一切普通组件，`z-index` 对它们无效。**

```tsx
// ❌ 错误 - z-index 无法覆盖原生组件
<Map style={{ position: 'relative' }} />
<Box style={{ position: 'absolute', zIndex: 9999 }}>
  这个遮罩无法覆盖 Map
</Box>

// ✅ 正确 - 使用 cover-view / cover-image 覆盖原生组件
<Map style={{ position: 'relative' }}>
  <CoverView style={{ position: 'absolute', top: 10, left: 10 }}>
    这样才能显示在 Map 上方
  </CoverView>
</Map>
```

| 原生组件 | z-index 有效？ | 解决方案 |
|----------|---------------|----------|
| `map` | ❌ 无效 | 使用 `cover-view` / `cover-image` |
| `video` | ❌ 无效 | 使用 `cover-view` / `cover-image` |
| `canvas` | ❌ 无效 | 使用 `cover-view` / `cover-image` |
| `camera` | ❌ 无效 | 使用 `cover-view` / `cover-image` |
| `live-player` | ❌ 无效 | 使用 `cover-view` / `cover-image` |
| 普通组件 | ✅ 有效 | 正常使用 z-index |

#### 3.4.3 cover-view 限制

`cover-view` 只支持有限的 CSS 属性：

```tsx
// cover-view 支持的样式（有限）
<CoverView
  style={{
    position: 'absolute',
    top: 10,
    left: 10,
    width: 100,
    height: 40,
    backgroundColor: 'rgba(0,0,0,0.5)',
    borderRadius: 8,  // 部分机型支持
    // ❌ 不支持：boxShadow、transform、animation 等
  }}
>
  <CoverView style={{ color: '#fff', fontSize: 14 }}>
    文本内容
  </CoverView>
</CoverView>
```

> 💡 **建议**：如果页面包含 `map`、`video` 等原生组件，在设计时就要考虑弹窗、遮罩等覆盖层的实现方式，可能需要特殊处理或避免在这些页面使用复杂的浮层交互。

## 九、自动化守卫

规范如果只靠人工 Code Review，执行强度会逐渐衰减。**必须配套自动化检查。**

### 9.1 ESLint / 自定义 Lint 规则

建议在 `eslint.config.js` 或通过自定义插件实现以下检查：

| 规则 | 说明 | 作用范围 |
|------|------|----------|
| `no-use-query` | 禁止 `useQuery` 在共享页面中出现 | `terminal-preview/**`, `miniapp-shell/**` |
| `no-inline-style-tag` | 禁止 `<style>` 标签（除非包裹 `isBrowserEnvironment()`） | 全局 |
| `no-html-elements` | 禁止 `div/span/img/button`，必须用跨平台原语 | `terminal-preview/**` |
| `no-layout-classname-only` | 检测 className 包含布局关键词但无对应 style | `terminal-preview/**` |
| `no-direct-lucide-import` | 禁止直接 import `lucide-react`，必须用 `lucide-compat` | 全局 |

**示例规则配置（伪代码）：**

```js
// eslint-plugin-miniapp-compat/rules/no-html-elements.js
module.exports = {
  create(context) {
    return {
      JSXOpeningElement(node) {
        const forbidden = ['div', 'span', 'img', 'button', 'input']
        if (forbidden.includes(node.name.name)) {
          context.report({
            node,
            message: `禁止使用 <${node.name.name}>，请使用跨平台原语 Box/Text/Image/Button`,
          })
        }
      },
    }
  },
}
```

### 9.2 PR 模板

在 `.github/PULL_REQUEST_TEMPLATE.md` 中强制勾选 Code Review 检查清单：

```markdown
## 小程序兼容性检查清单

请确认以下事项（不适用的请标注 N/A）：

### 基础规范
- [ ] 所有 flex/grid/position 布局属性在 style 中定义
- [ ] className 中的布局类有 style 等效
- [ ] fontSize/gap/padding 等视觉尺寸乘了 wxScale
- [ ] 使用 useState + useEffect，不使用 useQuery
- [ ] 图标使用 lucide-compat / Icon，不使用 emoji 或 Unicode
- [ ] 无 `<style>` 标签（或有 isBrowserEnvironment 判断）
- [ ] 使用 Box/Text/Image，无 div/span/img

### 架构规范
- [ ] 小程序页面基于 terminal-preview 组件复用
- [ ] 主色从 themeSettings.primaryColor 获取，无硬编码
- [ ] 自定义导航栏预留安全区域，使用 navigationStyle: 'custom'
```

### 9.3 CI 集成

```yaml
# .github/workflows/lint.yml
- name: Lint 小程序兼容性
  run: |
    pnpm eslint src/components/terminal-preview --rule 'miniapp-compat/no-html-elements: error'
    pnpm eslint miniapp-shell/src --rule 'miniapp-compat/no-use-query: error'
```

### 9.4 推荐执行优先级

1. **立即实施**：PR 模板（零成本）
2. **第一周**：`no-html-elements`、`no-inline-style-tag` 规则
3. **第二周**：`no-use-query`、`no-direct-lucide-import` 规则
4. **持续迭代**：`no-layout-classname-only`（复杂度较高）
