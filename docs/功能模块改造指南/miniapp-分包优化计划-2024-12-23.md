# 小程序分包优化计划

> 创建日期：2024-12-23
> 备份分支：`backup/miniapp-before-split-20251223`

## 一、问题诊断

### 1.1 当前主包大小

| 文件 | 大小 | 占比 | 说明 |
|------|------|------|------|
| `common.js` | 3.0 MB | 62% | 包含 45+ 页面组件（核心问题） |
| `prebundle/` | 1.4 MB | 29% | react-dom、vant/area-data、tailwind-merge 等 |
| `base.wxml` | 168 KB | 3% | 模板文件 |
| 其他 | ~300 KB | 6% | vendors、runtime、app.js 等 |
| **总计** | **~4.85 MB** | - | **超出限制 223%** |

### 1.2 根因分析

1. **`React.lazy()` 在小程序失效**
   - 主仓使用 `React.lazy()` 动态导入页面
   - 但 Taro/Webpack 打包时，小程序不支持 Code Splitting
   - 所有模块被合并进 `common.js`

2. **分包配置未生效**
   - 主入口 `pages/main/index` → `TerminalPreviewApp` → `TerminalPreview`
   - `TerminalPreview` 静态导入所有页面组件
   - 导致所有代码进入主包

3. **不必要的依赖**
   - `react-dom` (280KB)：小程序用 `@tarojs/react` 渲染，不需要
   - `vant/area-data` (160KB)：省市区数据，仅地址页需要
   - `tailwind-merge` (172KB)：可评估是否必要

## 二、优化目标

| 指标 | 当前 | 目标 | 说明 |
|------|------|------|------|
| 主包大小 | 4.85 MB | < 1.5 MB | 微信限制 |
| 分包 A（服务相关） | 112 KB | ~500 KB | 服务列表、详情、下单 |
| 分包 B（用户相关） | 76 KB | ~300 KB | 用户设置 |
| 分包 C（工作台）* | - | ~600 KB | 新增：陪诊员工作台 |
| 分包 D（营销）* | - | ~400 KB | 新增：会员、优惠券、积分 |

## 三、拆包策略

### 3.1 策略选择：**精简主包 + 原生分包跳转**

核心思路：
- **主包**：只保留首页（home）渲染逻辑
- **分包**：通过 Taro 原生页面 + `wx.navigateTo` 跳转
- **共享代码**：提取到 `common` chunk，分包按需引用

## 四、实施步骤

### Phase 1：创建精简版首页组件 [P0]

**目标**：主包只包含首页渲染逻辑

1. 创建 `miniapp-shell/src/components/TerminalPreviewLite.tsx`
   - 只导入首页需要的子组件
   - 不导入任何页面组件（ServicesPage、ProfilePage 等）
   - TabBar 点击通过 `wx.navigateTo` 跳转到分包

2. 修改 `miniapp-shell/src/runtime/terminal-preview-app.tsx`
   - 使用 TerminalPreviewLite 替换 TerminalPreview

**预期效果**：`common.js` 从 3.0MB 降到 ~500KB

### Phase 2：扩展分包页面 [P1]

**目标**：将现有分包页面扩展覆盖所有功能

1. 在 `packageB/` 新增用户相关页面
2. 新建 `packageC/` 陪诊员工作台分包
3. 新建 `packageD/` 营销中心分包
4. 新建 `packageE/` 分销中心分包

**每个分包页面模板**：
```tsx
// packageX/pages/xxx/index.tsx
import { View } from '@tarojs/components'
import { QueryClientProvider, QueryClient } from '@tanstack/react-query'
import { XxxPage as XxxPageComponent } from '@terminal-preview/components/pages/XxxPage'
// ... 标准包装代码
```

### Phase 3：优化 Prebundle 配置 [P2]

**目标**：减少不必要的依赖打包

1. 配置 `config/index.ts` 排除 `react-dom`
2. 将 `vant/area-data` 移到分包按需加载
3. 评估 `tailwind-merge` 是否可替换为更轻量方案

### Phase 4：配置分包引用关系 [P2]

**目标**：通过 Taro 的 `addChunkPages` 控制分包 chunk 引用

1. 配置 `commonChunks` 拆分公共代码
2. 配置各分包的 chunk 引用关系
3. 确保分包不会拉入主包代码

### Phase 5：验证与测试 [P3]

1. 构建生产版本：`NODE_ENV=production pnpm build:weapp`
2. 检查各包大小是否符合预期
3. 在微信开发者工具中验证功能完整性
4. 真机测试页面跳转流畅性

## 五、风险评估

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 分包跳转闪烁 | 用户体验下降 | 中 | 使用 preloadRule 预加载 |
| 共享状态丢失 | 功能异常 | 中 | 使用全局存储 + 页面参数传递 |
| 样式不一致 | 视觉问题 | 低 | 统一使用主仓组件 |
| 分包超限 | 无法发布 | 低 | 监控分包大小，按需拆分 |

## 六、回滚方案

