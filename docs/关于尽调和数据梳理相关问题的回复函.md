## 二、关于数据全生命周期环节缺失的回复

感谢贵方指出《数据字段梳理》中全生命周期环节的缺失。我司现补充**数据传输**与**数据销毁**环节的具体内容如下：

### 2.1 数据传输环节

#### （1）传输方式与加密

| 传输场景 | 传输协议 | 加密方式 | 说明 |
|----------|----------|----------|------|
| 客户端 ↔ 服务端 | HTTPS (TLS 1.2+) | TLS 加密传输 | 所有 API 请求均强制使用 HTTPS |
| 服务端 ↔ 微信支付 | HTTPS | TLS + 微信支付签名验证 | 支付报文使用 XML 格式，需 API 密钥签名 |
| 服务端 ↔ 短信服务 | HTTPS | TLS + 服务商 AK/SK 签名 | 仅传递手机号用于发送验证码 |
| 服务端 ↔ 数据库 | TCP | 内网通信（同服务器部署） | 数据库不对外暴露，仅限内网访问 |
| 客服聊天（WebSocket） | WSS | TLS 加密 | 实时通信使用加密 WebSocket |

#### （2）传输中的敏感数据保护

| 数据类型 | 传输保护措施 |
|----------|-------------|
| 身份证号 | HTTPS 传输加密；接口响应中脱敏展示（显示前6后4位） |
| 手机号 | HTTPS 传输加密；接口响应中脱敏展示（显示前3后4位） |
| 提现账户信息 | HTTPS 传输加密；加密存储后脱敏展示 |
| 支付信息 | HTTPS 传输；微信支付签名机制保障报文完整性与真实性 |

#### （3）数据跨境传输

本平台所有数据存储和处理均在**中国境内**完成，不存在数据跨境传输场景。

### 2.2 数据销毁环节

#### （1）数据保留期限

| 数据类别 | 保留期限 | 法规依据 |
|----------|----------|----------|
| 用户账号数据 | 用户主动注销后保留 **30天**（冷静期），期满后彻底删除 | 《个人信息保护法》第47条 |
| 订单与交易数据 | 自订单完成之日起保留 **3年** | 《电子商务法》第31条（不少于3年）、《税收征收管理法》 |
| 日志数据 | 保留 **1年** | 《网络安全法》第21条 |
| 陪诊员申请数据（被拒绝） | 审核拒绝后保留 **90天**，期满后删除 | 数据最小必要原则 |
| 客服聊天记录 | 保留 **1年** | 争议解决需要 |

#### （2）数据销毁方式

| 销毁场景 | 销毁方式 | 说明 |
|----------|----------|------|
| 用户注销账号 | 软删除（30天冷静期）→ 定时任务彻底删除个人数据 | 订单数据脱敏保留（财务合规） |
| 就诊人信息删除 | 级联删除（Cascade） | 删除用户时关联的就诊人信息同步删除 |
| 用户地址删除 | 级联删除（Cascade） | 删除用户时关联的地址信息同步删除 |
| 数据保留期满 | 定时任务自动清理 | 到期数据从数据库中物理删除 |
| 数据库备份文件 | 超过保留期的备份文件物理删除 | 备份数据同样遵循保留期限要求 |
| Redis 缓存数据 | 设置 TTL 自动过期 | 临时缓存数据到期后自动清除 |

#### （3）数据销毁流程

```
数据到达保留期限 → 定时任务触发 → 识别待销毁数据 → 执行删除操作 → 记录销毁日志 → 审计确认
```

#### （4）用户主动删除权

- 用户可在小程序内自助删除就诊人信息、地址信息
- 用户可申请注销账号，30天冷静期后彻底删除个人数据
- 陪诊员可申请退出平台，个人数据按保留期限处理

### 3.4 数据安全技术措施说明（补充）

| 安全措施 | 具体实施方案 |
|----------|-------------|
| 传输加密 | 全站强制 HTTPS（TLS 1.2+），WebSocket 使用 WSS 协议 |
| 存储加密 | 敏感字段（身份证号、提现账户等）使用 AES 加密存储 |
| 展示脱敏 | 手机号显示前3后4位，身份证号显示前6后4位 |
| 访问控制 | 基于 JWT Token 的身份认证 + 基于角色的权限控制（RBAC） |
| 密码安全 | 管理员密码使用 bcrypt 加密，JWT Secret 使用32位以上随机字符串 |
| 数据库安全 | 数据库仅限内网访问，不对外暴露端口 |
| 日志审计 | 关键操作（登录、支付、数据修改）记录操作日志 |
