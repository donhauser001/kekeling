# 全局终端预览器功能审计与小程序迁移评估报告

## 一、当前后台功能实现概览

基于代码审计，后台系统已实现以下功能模块：

### 1.1 用户域

- **用户管理**: 用户列表、详情、编辑 (`/admin/users`)
- **就诊人管理**: 就诊人 CRUD (`/patients`, `/admin/patients`)
- **地址管理**: 收货地址 CRUD (`/user/addresses`)
- **用户资料**: 头像、昵称、性别、生日 (`PUT /users/profile`)

### 1.2 陪诊员域

- **陪诊员管理**: 列表/详情/审核 (`/admin/escorts`)
- **等级体系**: 等级 CRUD (`/admin/escort-levels`)
- **标签管理**: 标签 CRUD (`/admin/escort-tags`)
- **分类管理**: 分类 CRUD (`/admin/escort-categories`)
- **身份认证**: 实名认证审核 (`/admin/escort-identity`)

### 1.3 订单域

- **用户端订单**: 创建/列表/详情/取消/评价/投诉 (`/orders`)
- **陪诊员端订单**: 抢单/到达/开始/完成 (`/escort/orders`)
- **后台订单管理**: 列表/派单/状态流转/退款 (`/admin/orders`)
- **智能派单**: 推荐/自动派单/批量派单

### 1.4 资金域

- **陪诊员钱包**: 余额/收入明细/交易流水 (`/escort/wallet`)
- **提现申请**: 申请提现 (`/escort/wallet/withdraw`)
- **提现管理**: 列表/审核/打款/导出 (`/admin/escorts/withdraw-records`)
- **佣金计算**: 抽佣服务 (`commission.service`)

### 1.5 服务域

- **服务管理**: CRUD/批量操作 (`/services`)
- **服务分类**: 分类 CRUD (`/service-categories`)
- **服务保障**: 保障项 CRUD (`/service-guarantees`)
- **定价系统**: 会员价/时段价 (`/pricing`)

### 1.6 营销域

- **优惠券**: 发放/领取/核销 (`/marketing/coupons`)
- **会员系统**: 会员等级/权益/套餐 (`/marketing/membership`)
- **积分系统**: 积分获取/消费/记录 (`/marketing/points`)
- **邀请有礼**: 邀请规则/记录 (`/marketing/referrals`)
- **活动管理**: 活动 CRUD (`/marketing/campaigns`)

### 1.7 分销域

- **分销设置**: 等级/分润规则 (`/admin/distribution`)
- **分销申请**: 申请/审核 (`/distribution/applications`)
- **分销中心**: 统计/成员/记录 (`/escort-app/distribution`)

### 1.8 内容域

- **CMS 页面**: 页面 CRUD (`/cms/pages`)
- **文章管理**: 文章 CRUD (`/cms/articles`)
- **文章分类**: 分类 CRUD (`/cms/article-categories`)
- **操作指南**: 指南管理 (`/operation-guides`)

### 1.9 医疗资源域

- **医院管理**: 医院 CRUD (`/hospitals`)
- **科室管理**: 科室 CRUD (`/departments`)
- **医生管理**: 医生 CRUD (`/doctors`)

### 1.10 系统配置

- **品牌设置**: Logo/名称/Slogan (`/config/brand`)
- **首页设置**: 模块开关/排序 (`/home/page-settings`)
- **轮播图**: 多区域轮播图 (`/admin/banners`)
- **主题设置**: 主色/暗色模式 (`/config/theme`)

## 五、关键能力缺口与改造建议

### 5.1 P0 级（必须解决）

1. **微信原生能力封装**

- 创建统一的 `wx-bridge.ts` 封装登录/支付/分享
- 预览器中使用 Mock 实现，小程序中切换真实实现

2. **订单投诉页面**

- 新增 `ComplaintPage.tsx`
- 对接 `POST /orders/:id/complaint` API

### 5.2 P1 级（建议解决）

1. **图片上传适配**

- 预览器使用 FileReader
- 小程序使用 wx.chooseImage + wx.uploadFile

2. **地理定位适配**

- 预览器使用 Geolocation API（浏览器）
- 小程序使用 wx.getLocation

### 5.3 P2 级（可选优化）

1. **离线缓存策略**

- 使用 React Query 的 persistQueryClient
- 小程序中使用 wx.setStorageSync

2. **性能优化**

- 页面懒加载已实现
- 可进一步优化图片懒加载

## 七、结论

全局终端预览器已覆盖 **95%** 的用户端和陪诊员端功能，具备良好的小程序迁移基础。主要缺口集中在微信原生能力（登录/支付/分享）和个别未实现页面（投诉）。

建议采用**桥接层模式**处理原生能力差异，保持预览器代码与小程序代码的最大复用。预计完整迁移周期为 **5-6 周**。
